HOW TO TEST RESONANT (chat-first tutor)
======================================
Run from the repo root unless a step says otherwise.
No API key needed for parts 1-2 and 4; parts 3 and 5 need one.

PART 0 - ONE-TIME SETUP CHECK
-----------------------------
1. flutter --version        (want Flutter 3.27+, Dart 3.6+)
2. node --version           (want Node 20.17+)
3. cd backend && npm install && cd ..
   (skip if backend/node_modules already exists)
4. Backend key (only needed for parts 3 and 5):
   copy backend/.env.example to backend/.env and set MODEL_API_KEY.
   Get a key at https://dev.meta.ai/platform

PART 1 - AUTOMATED TESTS (no key needed, ~2 min)
-----------------------------------------------
1. flutter analyze
   Expect: "No issues found!"
2. flutter test
   Expect: "All tests passed!" (372 tests)
3. cd backend && npm test
   Expect: pass 36, fail 0. Then cd .. back to the root.

PART 2 - BACKEND WITHOUT A KEY (no key needed)
----------------------------------------------
1. cd backend && npm start
   Expect: "Resonant backend on http://localhost:3000"
   and "No MODEL_API_KEY set: only the sample picture will work."
2. In a second terminal:
   - curl http://localhost:3000/api/health
     Expect: {"ok":true,"metaConfigured":false,...}
   - curl http://localhost:3000/api/samples
     Expect: two samples, ids "chart" and "sample".
   - POST analyze with no key (must fail gracefully, not crash):
     curl -X POST http://localhost:3000/api/analyze -H "Content-Type: application/json" -d "{}"
     Expect: HTTP 503 with "no Meta API key ... try the sample picture".
   - POST chat with no key:
     curl -X POST http://localhost:3000/api/chat -H "Content-Type: application/json" -d "{\"question\":\"hi\"}"
     Expect: HTTP 503 with "no Meta API key".
3. Stop the server with Ctrl+C.

PART 3 - BACKEND WITH A KEY (key needed)
----------------------------------------
1. cd backend && npm start (with backend/.env holding MODEL_API_KEY).
2. In a second terminal: npm run check:api
   Expect: Spark answers, parts listed, each part shows box=left,top,right,bottom.
   If regions is empty, Spark gave no usable boxes - try another picture.
3. Box quality check:
     node scripts/try-image.js path/to/your/picture.jpg
   Expect: parts printed with % of picture + box coords, then an
   "Overlay (open in a browser): ..." path. Open it: each box should hug
   its part. Loose boxes = tune the `where` rule in backend/server/meta.js.
4. Analyzed-once caching: analyzing the same picture twice (via the app,
   part 5) pays once - the second open is instant.

PART 4 - RUN THE APP, NO KEY (samples + lessons only)
-----------------------------------------------------
1. Pick a target:
   - Web (quickest):  flutter run -d chrome
   - Android emulator: start the emulator, then: flutter run
   - Real phone: connect it, then: flutter run
2. Home shows five lines: Chat, Lessons, Quiz, Settings, Quit.
3. Open Chat. It greets you with no picture attached.
   - Type or speak a question about one of the six lesson topics
     (photosynthesis, cells, ecosystems, plant adaptations, binary
     search, plate tectonics): the built-in lessons answer, and the
     app says the answer is from the lesson.
   - Ask anything else: it says it has no lesson on that and lists
     the topics. This is the expected keyless behavior, not a bug.
4. Tap the camera button on the ask bar. The sheet offers: Take photo,
   Choose from gallery, Try a sample, plus recents once you have any.
   - Tap a sample: it attaches instantly (no key needed) and the chat
     announces its title, parts and overview. Questions now go to the
     AI tutor - without a key it says it can't reach the server and
     falls back to the lessons, with the Offline banner showing.
   - Take photo / Choose without a key: analyzing fails gracefully
     with a spoken error. Nothing crashes, nothing stalls silently.
5. Lessons: open a lesson, it reads itself; swipes move through it.
   Quiz: start a set, answer, retry rounds work - all offline.
6. Settings: switch themes/fonts/sizes (each previews before keeping).

PART 5 - RUN THE APP WITH A KEY (full tutor, end to end)
--------------------------------------------------------
1. Start the backend WITH the key: cd backend && npm start.
   Find your computer's LAN IP (ipconfig, IPv4 Address).
2. Run the app pointed at it:
     flutter run --dart-define=API_BASE=http://<your-computer-ip>:3000
   (On the Android emulator you can use http://10.0.2.2:3000 instead.
   On web, API_BASE defaults to the page origin.)
3. Open Chat, tap the camera button, take a NEW photo.
   Expect: "Reading the picture...", spoken progress as each part
   lands, then "Title. N parts: ... Overview. Ask me anything about it."
4. Hold a conversation: ask a question by voice (tap, speak, tap) or
   type it. Follow up ("and why?") - the tutor remembers the last six
   exchanges. Answers are spoken and shown as swipable sentences;
   swipe through them, tap an edge to stop the voice.
5. Attach another picture mid-conversation: a fresh conversation
   starts about it (announced, never silent).
6. Reopen a recent from the sheet: instant, no model calls.
7. Talk live: hidden unless you run with
     --dart-define=LIVE_VOICE=true
   and only works with the agent running (cd agent, see agent/README.md)
   plus LiveKit creds. With a picture attached, a Talk live button
   appears in chat. First on-phone call is still unproven - expect
   rough edges there.

PART 6 - WHAT "GOOD" LOOKS LIKE (checklist)
-------------------------------------------
- check:api prints a box for every part, none missing.
- Attaching announces title + parts + overview, every time.
- Follow-ups reference earlier answers (history flows).
- Every failure speaks a plain sentence; nothing stalls silently.
- Full suite still green after any change: flutter analyze, flutter
  test, cd backend && npm test.

TROUBLESHOOTING
---------------
- App cannot reach server: same Wi-Fi? IP correct? Windows Firewall
  allowing Node? Try opening http://<ip>:3000/api/health in the phone's
  browser first.
- Port 3000 busy: set PORT=3001 in backend/.env and point API_BASE there.
- 422 "No parts could be placed": picture too vague - try one with
  distinct shapes.
- TalkBack/VoiceOver on: one-finger touch goes to the screen reader -
  use the buttons instead.
